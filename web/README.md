# σ実測ツール

き裂の追跡測定において、**その機材・その現場で何mmの変化まで検出できるか**を実測するツールです。

## 考え方

構造物は数分では動きません。だから同じ場所から連続で撮った複数枚に対して変位を計算すると、
**出るはずのない値**が出ます。それがそのまま測定ノイズ σ です。3σ が実質的な検出限界になります。

目標精度を先に決めるのではなく、**現物の σ を測ってから「何mmの変化なら有意と言えるか」を決める**、
という順序のためのツールです。

### 画面の作り

カメラアプリの構成です。スクロールしません。

```
┌──────────────────────────────────┬────┐
│ HUD  枚数 mm/px 距離 斜角 検出限界 │写真│  ← 数値は常時表示・押すと該当シート
│ ┌──────────────────────────────┐ │スケール│
│ │                              │ │点群│
│ │   ビューファインダー          │ │範囲│  ← 各項目にドット
│ │   （写真とドラッグ選択）      │ │結果│     灰=未評価 緑=良好
│ │                              │ │経時│     橙=注意 赤=不可
│ └──────────────────────────────┘ │ ◉  │  ← その場で撮影
│ 撮影品質 │ 検出限界 3σ │ 前回との差 │ σ  │  ← σ を実測する
└──────────────────────────────────┴────┘
```

縦持ちではレールが下に回ります。σ ボタンは親指の届く位置に固定です。

**常時表示にした理由** — 縦に積むと「撮り直すべき状況」（ピントが甘い・
模様が無い・斜めすぎる）に気づくのが現場を離れた後になります。
判断に必要な数値は常に画面に置き、詳細だけをシートへ追い出しています。

- **σ ボタンは常に押せます。** 条件が足りなければ理由を言って、直せる場所まで
  連れて行きます（「σ は動いていないはずのものが動いて見える量なので2枚以上必要です」等）
- **撮影品質は「一番悪い1枚」を出します。** 1枚でもピントが外れていれば
  セッション全体の σ が悪化するので、最新や平均では見逃します
- **ビューファインダーの一言**は「撮り直すべき」＞「次にやること」の順。
  問題も不足も無ければ黙ります

### 手順

1. 写真を読み込む（**◉** ボタン、またはドロップ／選択）
2. スケールを決める — 次の3通りのどれかで。採用したものは画面に出ます
   - 既知の基準距離（最も確か）
   - 点群（斜め補正まで入る／後述）
   - 撮影距離 × 焦点距離
3. ビューファインダー上でドラッグして解析範囲を選ぶ（未選択なら短辺60%の正方形）
4. **σ** ボタン

写真は**追加していけます**。カメラは1回1枚しか返さないので、撮るたびに積み上がります。

### 現地チェック（1枚から効きます）

σ の実測には2枚以上必要ですが、**「この位置で撮って意味があるか」は1枚で分かります。**
写真を1枚読み込んだ時点で、模様の有無・ピント・分解能を即座に判定します。
撮り直しが効くうちに気づくのが目的です。

セッション内でピントが明らかに外れている枚も指摘します
（ピントの絶対値はレンズと被写体で変わるため、中央値との比較で判定しています）。

### オフラインで動きます

一度開けばサービスワーカーがアプリ本体をキャッシュするので、**圏外の現場でも動きます**。
解析はもともとブラウザ内で完結するので、通信は一切必要ありません。
iPhone なら「ホーム画面に追加」しておくとアプリのように起動できます。

## 点群を併せて使う（写真との「良いとこどり」）

Scaniverse などで撮った点群（PLY / LAS）を読み込めます。**写真が無くても使えます。**

役割は重なりません。それぞれ得意な量だけを出させます。

| | 面内（き裂の開き） | 面外（はらみ出し） | スケール |
|---|---|---|---|
| 写真 | **0.035mm** | 出ない | 自前では決まらない |
| 点群 | 5〜15mm（話にならない） | **5〜15mm（唯一の手段）** | **実寸で入っている** |

点群にできて写真にできないのは**面外**です。石材は抜け落ちる前に手前へ膨らみます。
これは写真1組からは原理的に出ません。逆にき裂の開きは写真が2桁上なので、
点群には一切やらせていません。

### 点群が渡してくれるもの

1. **スケール** — 面までの距離と**斜角**が決まります。
   斜めに構えると mm/px は 1/cosθ で伸びるので、距離と焦点距離だけで計算すると
   系統的に過小評価します（30° で 15%、45° で 41%。合成データで検証済み）。
   点群を使うとこの補正が入ります。画素の隣を実際に平面へ飛ばして
   交点間の距離を測っているので、cosθ の近似ではなく厳密解です。
2. **面外のはらみ出し** — 平面からの残差を石材スケールのセルに集約した図。
   セルの代表値は中央値なので、手前の草を一掴みしても面が残ります。
   検出限界は**その点群自身の面の粗さ（RMS）の3倍**。σ実測と同じ考え方で、
   点群自身に「何mmなら本物と言えるか」を決めさせています。

### 撮影手順

**スキャンを開始した位置から写真を撮ってください。**
点群の原点＝スキャン開始地点なので、これで視点が決まります。
点群と写真の厳密な位置合わせはしません。

立ち位置が 10m に対して 0.3m ずれた場合のスケール誤差は 3%。
追跡計測（変化量）ではこれは変化量の 3% にしか効かないので
（0.10mm の開きに対して 0.003mm）実質無視できます。
絶対幅を出すときだけ 3% が効きます。

LAZ（圧縮 LAS）は読めません。LAS か PLY で書き出してください。

## 撮影プロトコル

### 枚数を稼ぐなら「連写」が最適

**iPhone の Camera アプリでシャッターを長押し（またはボリューム下を長押し）**すると
10fps のバーストになります。2秒で20枚撮れるので、その間の気温変化も日射変化もほぼゼロ。
撮った後にライブラリから全選択してこのツールに渡してください。

アプリ内の「その場で撮影」ボタンは1タップ1枚なので、現地チェック用と割り切っています。

### 注意点

1. **ズーム倍率を固定し、撮影中に一切触らない** — 焦点距離が変わるとスケールが変わり、
   追跡測定が静かに壊れます。ツールが EXIF を照合して不一致を警告します
2. AE/AF ロック
3. **JPEG 推奨**（設定 > カメラ > フォーマット > 互換性優先）。
   Chrome は HEIC を読めません。Safari なら HEIC でも通ります
4. 曇天か日陰の時間帯（影のコントラストが変わると相関が落ちます）
5. 気温・天候・時刻を記録（温度による見かけの開閉を後で分離するため）

## 結果の読み方

| 表示 | 意味 |
|---|---|
| テクスチャ判定 | DIC が成立する模様があるか。`poor` ならターゲット方式へ |
| σ (px) | 1測点・1枚あたりの測定ノイズ |
| 検出限界 3σ | き裂を挟む2点の相対変位として検出できる下限 |
| 残差ベクトル図 | **方向がランダムならノイズ**。揃っていたり渦を巻いていたら、変換モデルで取り切れていない歪み（レンズ歪、または被写体の実際の動き）が残っています |

N枚平均すると σ は √N で下がります。表の下に平均後の値も出ます。

## 何を測っているか

```
基準画像 ─┬─→ 各画像との変位場（DIC: ZNCC探索 → 逆合成Gauss-Newton）
          │
          ├─→ カメラの動きをアフィン/ホモグラフィで当てはめて差し引く
          │
          └─→ 残った散らばり = 測定ノイズ σ（MADベースでロバストに算出）
```

相関の指標に **ZNSSD**（ゼロ平均正規化二乗差）を使っているため、
撮影ごとの明るさ・コントラストの違いには影響されません。

変換モデルは用途で選びます。

- **アフィン** — 三脚＋連写。並進・回転・スケール・せん断
- **ホモグラフィ** — 手持ちや別日撮影。平面を仮定した射影変換

## 端末を問いません

校正が必要である以上、端末固有のAPI（ARKit の内部パラメータなど）には依存しない設計です。
iPhone、Android、ミラーレスで撮った画像がすべて同じ土俵に乗ります。

## 模擬マーカーでのテスト

**[targets/](targets/)** を開いて「印刷する」を押し、A4 に**原寸（100%）で印刷**してください。
プリンタの既定は「用紙に合わせる」で約96%に縮むので、シート上のスケールバーを
定規で測って 100.0mm であることを必ず確認してください。

> 素の SVG（`targets/target-sheet-A4.svg`）も置いてありますが、
> GitHub 上ではブラウザによって表示されないことがあります。
> **HTML 版（`targets/`）を使ってください** — 印刷ボタンと A4 の印刷指定が入っています。

シートは左右2枚に分かれます。

- **固定側 A**（3点）— 壁に貼って動かさない。剛体基準になります
- **可動側 B**（3点）— 既知量だけ動かす。き裂の向こう側の役

### 手順

1. 破線で切り、A側だけを壁や板にしっかり貼る
2. B側をA側の横に隙間を空けて仮止めする
3. **A1–A3 の実距離をノギスで実測**（印刷倍率の誤差を吸収するため）
4. 動かさずに10〜20枚撮る → **σ（測定ノイズ）が出る**
5. B側だけを既知量ずらす（すきまゲージ 0.10mm 等を挟む）→ もう10枚撮る
6. ツールが**その既知量を当てられるか**確認する

ツール側では「解析方式」を **ターゲット** または **両方** にしてください。
「両方」を選ぶと DIC と併走し、両者の食い違いから
**ターゲットが浮いていないか**を確認できます（実運用では接着不良の検出に使えます）。

スケールは「既知の基準距離」欄に A1–A3 の実測値を入れるのが最も正確です。
レーザー距離計も焦点距離も不要になり、印刷倍率の誤差も吸収できます。

### ターゲット検出の検証結果

```bash
node test/run.mjs
```

| 項目 | 結果 |
|---|---|
| 重心のサブピクセル精度 | 誤差 **0.0033 px**（1/300px） |
| 露出+40%・オフセット変化 | ずれ **0.00000 px**（完全に非依存） |
| ノイズ振幅2%（8bit で ±2.6階調） | 誤差 0.019 px |
| 斜め45°相当の楕円 | 誤差 0.0011 px |

## 経時管理

測点を登録して、解析のたびに1回ぶんの観測として積みます。
履歴はこの端末のブラウザにだけ保存されます（サーバーには何も送りません）。
端末を替えると消えるので、**JSON の書き出しを「保存」として扱ってください**。

### 差の検出限界は 1日ぶんの 3σ より広い

2時期を比べるときは**両日のばらつきが乗る**ので、差の分散は σ_A² + σ_B²。
同じ精度で撮れていれば、差の限界は 1日ぶんの 3σ の **√2 倍**に広がります。

σ が 0.03mm なら、1日ぶんの 3σ は 0.090mm ですが、
前回との差で有意と言えるのは **0.127mm** から。ここを間違えると
有意でない変化を「進行」と報告してしまいます。

### 温度による見かけの開閉を分離する

き裂は温めれば閉じ、冷やせば開きます。これは進行ではありません。

**係数は文献から借りず、その測点自身のデータから回帰で出します。**
石材・目地・拘束条件で実効係数は変わるので、借り物の値は当てになりません。
時間と温度を同時に入れた重回帰にして、「温度で説明できるぶんを除いた
正味の経年変化」を出します。

これは前回比較にも効かせています。効かせないと、進行していないき裂でも
**毎回「有意な変化」と出ます**（夏冬交互に測れば温度による開閉がそのまま差になる）。
傾きは「進行なし」なのに前回比較だけが赤く光る、という食い違いが起きます。

分離には**季節を変えた観測**が要ります。気温の幅が 0.5K 未満だと分離せず、
「この傾きには温度が混ざっている可能性がある」と明示します。

### 使い方

1. 測点を追加（名前・部材・しきい値）
2. σ を実測したあと「この測点の観測として記録」
   - 計測値はターゲット対の距離、または手入力（ノギス実測など）
   - **気温を毎回入れる**。これが無いと温度分離ができません
3. 2回目から差の判定、3回目から傾き、季節をまたいで4回目から温度分離

σ を空のまま記録すると差だけ残り、有意判定はしません。

### 経時管理の検証結果

| 項目 | 結果 |
|---|---|
| 差の検出限界 | 片方の 3σ の √2 倍を返す |
| 傾き 0.050mm/年 の復元 | 0.0535mm/年（95%CI が真値を 38/40 で含む） |
| 動いていない測点の偽陽性 | 40件中 **2件**（95%水準どおり） |
| 温度係数 −0.004mm/K の復元 | **−0.00396mm/K** |
| 温度と進行が同時にある系列 | 進行 0.0405（真値 0.040）・温度 −0.00374（真値 −0.004） |
| 温度を無視した前回比較 | 有意と誤判定 → 分離すると有意でなくなる |

### 点群まわりの検証結果

| 項目 | 結果 |
|---|---|
| はらみ出し 20mm の復元 | **19.9mm**（位置誤差 35mm） |
| 外れ値（手前の植生）12% での平面法線 | 一致度 **1.0000**（主成分分析だと 90° 飛ぶ） |
| 平坦な壁での偽陽性 | **0 箇所** |
| 斜角 30° を無視したときの mm/px 誤差 | 15.4% 過小（理論 15.5%） |
| 斜角 40° での異方性 | 1.3065（理論 1.3054） |
| PLY (binary) / LAS 1.2 の読み取り | 座標誤差 2.4e-7 / 5.0e-4 |

石材・目地・拘束条件で実効係数は変わるので、借り物の値は当てになりません。
時間と温度を同時に入れた重回帰にして、「温度で説明できるぶんを除いた
正味の経年変化」を出します。

これは前回比較にも効かせています。効かせないと、進行していないき裂でも
**毎回「有意な変化」と出ます**（夏冬交互に測れば温度による開閉がそのまま差になる）。
傾きは「進行なし」なのに前回比較だけが赤く光る、という食い違いが起きます。

分離には**季節を変えた観測**が要ります。気温の幅が 0.5K 未満だと分離せず、
「この傾きには温度が混ざっている可能性がある」と明示します。

### 使い方

1. 測点を追加（名前・部材・しきい値）
2. σ を実測したあと「この測点の観測として記録」
   - 計測値はターゲット対の距離、または手入力（ノギス実測など）
   - **気温を毎回入れる**。これが無いと温度分離ができません
3. 2回目から差の判定、3回目から傾き、季節をまたいで4回目から温度分離

σ を空のまま記録すると差だけ残り、有意判定はしません。

### 経時管理の検証結果

| 項目 | 結果 |
|---|---|
| 差の検出限界 | 片方の 3σ の √2 倍を返す |
| 傾き 0.050mm/年 の復元 | 0.0535mm/年（95%CI が真値を 38/40 で含む） |
| 動いていない測点の偽陽性 | 40件中 **2件**（95%水準どおり） |
| 温度係数 −0.004mm/K の復元 | **−0.00396mm/K** |
| 温度と進行が同時にある系列 | 進行 0.0405（真値 0.040）・温度 −0.00374（真値 −0.004） |
| 温度を無視した前回比較 | 有意と誤判定 → 分離すると有意でなくなる |
