# σ実測ツール

き裂の追跡測定において、**その機材・その現場で何mmの変化まで検出できるか**を実測するツールです。

## 考え方

構造物は数分では動きません。だから同じ場所から連続で撮った複数枚に対して変位を計算すると、
**出るはずのない値**が出ます。それがそのまま測定ノイズ σ です。3σ が実質的な検出限界になります。

目標精度を先に決めるのではなく、**現物の σ を測ってから「何mmの変化なら有意と言えるか」を決める**、
という順序のためのツールです。

## 使い方

### → **https://kiyoshi-terrain.github.io/crack_tracking/**

> 初回のみ Settings → Pages → Source を「GitHub Actions」に設定してください。

ブラウザだけで動きます。サーバー処理も通信も無く、**画像がブラウザの外に出ることはありません**。
スマホからでもそのまま開けます。

ローカルで動かす場合:

```bash
cd web
python3 -m http.server 8080
# → http://localhost:8080
```

`file://` で直接開くと ES モジュールが CORS で弾かれるため、簡易サーバー経由で開いてください。

1. 写真を読み込む（**その場で撮影** ボタン、またはドロップ／選択）
2. 撮影距離（レーザー距離計の実測値）を入力 — mm換算にだけ必要
3. 解析範囲をドラッグで選択
4. 「σ を実測する」

写真は**追加していけます**。カメラは1回1枚しか返さないので、撮るたびに積み上がります。

### 現地チェック（1枚から効きます）

σ の実測には2枚以上必要ですが、**「この位置で撮って意味があるか」は1枚で分かります。**
写真を1枚読み込んだ時点で、模様の有無・ピント・分解能を即座に判定します。
撮り直しが効くうちに気づくのが目的です。

セッション内でピントが明らかに外れている枚も指摘します
（ピントの絶対値はレンズと被写体で変わるため、中央値との比較で判定しています）。

### オフラインで動きます

一度開けばサービスワーカーがアプリ本体をキャッシュするので、**圏外の現場でも動きます**。
解析はもともとブラウザ内で完結するので、通信は一切必要ありません。
iPhone なら「ホーム画面に追加」しておくとアプリのように起動できます。

## 撮影プロトコル

### 枚数を稼ぐなら「連写」が最適

**iPhone の Camera アプリでシャッターを長押し（またはボリューム下を長押し）**すると
10fps のバーストになります。2秒で20枚撮れるので、その間の気温変化も日射変化もほぼゼロ。
撮った後にライブラリから全選択してこのツールに渡してください。

アプリ内の「その場で撮影」ボタンは1タップ1枚なので、現地チェック用と割り切っています。

### 注意点

1. **ズーム倍率を固定し、撮影中に一切触らない** — 焦点距離が変わるとスケールが変わり、
   追跡測定が静かに壊れます。ツールが EXIF を照合して不一致を警告します
2. AE/AF ロック
3. **JPEG 推奨**（設定 > カメラ > フォーマット > 互換性優先）。
   Chrome は HEIC を読めません。Safari なら HEIC でも通ります
4. 曇天か日陰の時間帯（影のコントラストが変わると相関が落ちます）
5. 気温・天候・時刻を記録（温度による見かけの開閉を後で分離するため）

## 結果の読み方

| 表示 | 意味 |
|---|---|
| テクスチャ判定 | DIC が成立する模様があるか。`poor` ならターゲット方式へ |
| σ (px) | 1測点・1枚あたりの測定ノイズ |
| 検出限界 3σ | き裂を挟む2点の相対変位として検出できる下限 |
| 残差ベクトル図 | **方向がランダムならノイズ**。揃っていたり渦を巻いていたら、変換モデルで取り切れていない歪み（レンズ歪、または被写体の実際の動き）が残っています |

N枚平均すると σ は √N で下がります。表の下に平均後の値も出ます。

## 何を測っているか

```
基準画像 ─┬─→ 各画像との変位場（DIC: ZNCC探索 → 逆合成Gauss-Newton）
          │
          ├─→ カメラの動きをアフィン/ホモグラフィで当てはめて差し引く
          │
          └─→ 残った散らばり = 測定ノイズ σ（MADベースでロバストに算出）
```

相関の指標に **ZNSSD**（ゼロ平均正規化二乗差）を使っているため、
撮影ごとの明るさ・コントラストの違いには影響されません。

変換モデルは用途で選びます。

- **アフィン** — 三脚＋連写。並進・回転・スケール・せん断
- **ホモグラフィ** — 手持ちや別日撮影。平面を仮定した射影変換

## 端末を問いません

校正が必要である以上、端末固有のAPI（ARKit の内部パラメータなど）には依存しない設計です。
iPhone、Android、ミラーレスで撮った画像がすべて同じ土俵に乗ります。

## 検証

```bash
node test/run.mjs
```

既知の変位を与えた合成テクスチャで、アルゴリズムの正しさを確認しています
（連続関数を格子点で標本化しているため、真値に補間誤差が入りません）。

現在の結果:

| 項目 | 結果 |
|---|---|
| サブピクセル変位の復元 | 誤差 0.001〜0.005 px |
| 露出+35%・オフセット変化 | 影響なし（ZNSSD） |
| ノイズ振幅1%（8bit で ±1.3階調） | 誤差 0.005 px |
| 手持ち相当のずれ（50px超） | 粗いアライメント後 0.003 px |

合成データなので実写より良く出ます。**実写の σ を測るのがこのツールの目的**です。

## 模擬マーカーでのテスト

**[targets/](targets/)** を開いて「印刷する」を押し、A4 に**原寸（100%）で印刷**してください。
プリンタの既定は「用紙に合わせる」で約96%に縮むので、シート上のスケールバーを
定規で測って 100.0mm であることを必ず確認してください。

> 素の SVG（`targets/target-sheet-A4.svg`）も置いてありますが、
> GitHub 上ではブラウザによって表示されないことがあります。
> **HTML 版（`targets/`）を使ってください** — 印刷ボタンと A4 の印刷指定が入っています。

シートは左右2枚に分かれます。

- **固定側 A**（3点）— 壁に貼って動かさない。剛体基準になります
- **可動側 B**（3点）— 既知量だけ動かす。き裂の向こう側の役

### 手順

1. 破線で切り、A側だけを壁や板にしっかり貼る
2. B側をA側の横に隙間を空けて仮止めする
3. **A1–A3 の実距離をノギスで実測**（印刷倍率の誤差を吸収するため）
4. 動かさずに10〜20枚撮る → **σ（測定ノイズ）が出る**
5. B側だけを既知量ずらす（すきまゲージ 0.10mm 等を挟む）→ もう10枚撮る
6. ツールが**その既知量を当てられるか**確認する

ツール側では「解析方式」を **ターゲット** または **両方** にしてください。
「両方」を選ぶと DIC と併走し、両者の食い違いから
**ターゲットが浮いていないか**を確認できます（実運用では接着不良の検出に使えます）。

スケールは「既知の基準距離」欄に A1–A3 の実測値を入れるのが最も正確です。
レーザー距離計も焦点距離も不要になり、印刷倍率の誤差も吸収できます。

### ターゲット検出の検証結果

```bash
node test/run.mjs
```

| 項目 | 結果 |
|---|---|
| 重心のサブピクセル精度 | 誤差 **0.0033 px**（1/300px） |
| 露出+40%・オフセット変化 | ずれ **0.00000 px**（完全に非依存） |
| ノイズ振幅2%（8bit で ±2.6階調） | 誤差 0.019 px |
| 斜め45°相当の楕円 | 誤差 0.0011 px |
| **模擬き裂の開口 0.37px** | **誤差 0.0022 px で復元** |
| 手持ち相当のずれでの対応付け | 正しく対応 |

しきい値で2値化した図心ではなく**輝度加重重心**を使っているため、
しきい値の取り方で重心が動きません。これが 1/300px の根拠です。
